### التنبؤ بالمانيڤست المدمج (Merged Manifest)

فُحصت مانيڤستات كل الإضافات أندرويد الفعلية (audio_service 0.18.19، audio_session 0.2.4، just_audio 0.10.6، sqflite_android، shared_preferences_android، jni، jni_flutter، path_provider_android): **كلها فارغة أو بلا أذونات — الإضافات تضيف صفر أذونات وصفر مكوّنات مُصدَّرة.**

قائمة الصيد — **غير موجودة في أي مكان** (بحث = 0): `AD_ID`، `READ_EXTERNAL_STORAGE`، `READ_MEDIA_*`، `RECORD_AUDIO`، `QUERY_ALL_PACKAGES`، `REQUEST_INSTALL_PACKAGES`، `SYSTEM_ALERT_WINDOW`، `SCHEDULE_EXACT_ALARM`، `ACCESS_NETWORK_STATE`، `RECEIVE_BOOT_COMPLETED`، أي `BIND_*`، وصولية (Accessibility). **لا حاجة لأي `tools:node="remove"` بناءً على الأدلة الحالية.**

⚠️ **طبقة وحيدة غير قابلة للفحص هنا:** مكتبات AAR الأصلية التي تجلبها ملفات Gradle للإضافات (media3-exoplayer 1.4.1 عبر just_audio، androidx.media/core عبر audio_service). لا توجد Java ولا مخرجات بناء في هذه البيئة. التوقع: القائمة النهائية = أذونات التطبيق الخمسة + إذن توقيع تلقائي من androidx.core. **إجراء مطلوب بعد بناء Windows:** فحص المانيڤست المدمج في `build/app/intermediates/merged_manifest/release/` أو قائمة أذونات Play Console، وإن ظهر إذن من قائمة الصيد يُزال بسطر (بعد إضافة `xmlns:tools` لجذر المانيڤست):
```xml
<uses-permission android:name="android.permission.XXX" tools:node="remove"/>
```
لا تُزل `WAKE_LOCK`/`ACCESS_NETWORK_STATE` إن ظهرا من Media3 — طبيعيان ومنخفضا الخطورة.

### أمان البيانات — بندًا ببندًا مقابل الكود الفعلي

أساس الكود: لا حسابات، لا تحليلات/إعلانات/مكتبات تقارير أعطال، الشبكة فقط لبث/تنزيل mp3quran، التخزين محلي (قاعدة sqflite: تقدم الحفظ/المفضلة/النطاقات/الجلسات/الأهداف + SharedPreferences: الإعدادات وعلامة الوقوف + ملفات MP3 منزّلة في مساحة التطبيق الخاصة). لا شيء من ذلك يُرسل خارج الجهاز أبدًا.

| حقل Play | الإجابة | السبب |
|---|---|---|
| بيانات تُجمع (أي نوع) | **لا** | تعريف Play للجمع = النقل خارج الجهاز؛ كل البيانات محلية فقط |
| بيانات تُشارك | **لا** (مع ملاحظة IP أدناه) | لا يُرسل أي بيانات مستخدم لأي طرف |
| معلومات شخصية/مالية/صحية/رسائل/جهات اتصال/تقويم/موقع/سجل ويب | لا | لا تُطلب ولا تُقرأ ولا تُحفظ أصلًا |
| صور/فيديو/صوتيات/ملفات | لا | لا ميكروفون (لا RECORD_AUDIO)، الصوت يتدفق واردًا فقط بطلب المستخدم |
| نشاط التطبيق | لا يُجمع | التقدم والجلسات محلية فقط |
| أداء التطبيق/الأعطال | لا | لا SDK لذلك |
| معرّفات الجهاز | لا | لا AD_ID ولا Android ID؛ حزمة uuid الانتقالية تولّد معرّفات عشوائية داخلية لمصادر الصوت فقط، ليست معرّف جهاز ولا تُنقل |
| التشفير أثناء النقل | نعم | HTTPS فقط |
| إنشاء حساب / رابط حذف حساب | لا ينطبق | لا حسابات |
| حذف البيانات | مسح بيانات التطبيق/إلغاء التثبيت + حذف التنزيلات من داخل التطبيق | لا نسخة خادمية أصلًا |

> ⚠️ **ملاحظة عنوان IP (بأمانة كاملة):** البث/التنزيل يكشف بالضرورة عنوان IP الجهاز (وترويسات HTTP القياسية) لخادم `cdn.mp3quran.net` في سجلاته — ضرورة شبكية يبدأها نقر المستخدم. المطوّر لا يتلقى ولا يتحكم ولا يخزّن شيئًا من ذلك، والتطبيق لا يرسل أي حمولة عن المستخدم أو نشاطه. الإعلان التقليدي الصحيح لهذا الشكل هو **«لا جمع / لا مشاركة»** مع إفصاح IP في سياسة الخصوصية — وهو ما تفعله `privacy-policy.html` بالعربية والإنجليزية. يجب أن يطابق نموذج أمان البيانات السياسةَ تمامًا؛ إعلان أنواع «مُجمعة/مُشاركة» في النموذج بينما تقول السياسة العكس هو بحد ذاته سبب رفض محتمل.
